# Physics playground

Open `Assets/Scenes/TrainPlayground.unity` and press Play. WASD moves, mouse looks, Space jumps. Hold left or right mouse to reach and grip with that hand; release to let go. Escape frees the cursor and clicking the Game view captures it again.

Choose **Spelen** in the menu to start a local Netcode for GameObjects host. The server controls the capsule body, upright balance, movement, jump, jointed physics arms and legs, and spring grips. The continuous conductor mesh is skinned at runtime to the existing leg anchors; its importer needs Read/Write enabled. The server sends limb rotations to observers. Arm/torso collisions are enabled, with restricted shoulder joints. A released button, lost window focus or stale input clears the grip on the server. Hands can grip static geometry and server-owned, spawned network rigidbodies. The scene includes a server-authoritative test crate with NetworkRigidbody and NetworkTransform. Static train meshes use non-convex mesh colliders; a moving train needs suitable dynamic shapes and a separate network physics design.

This remains a physics prototype: skin weights are generated from position and require visual tuning; there are no individual finger joints. The grip attaches to an arm rigidbody at the hand position. The trial spawns a server-owned scene player for the host and an owned prefab for each connecting client. Reconciliation, simultaneous grabs, late join, disconnect handling, latency and a moving train still need end-to-end tests before this can be treated as a complete multiplayer controller.

On 2026-11-03 an editor-only host smoke probe moved the player in an empty area, requested a jump and created a temporary static wall at the left hand: movement, a 0.43 m jump and spring-joint creation all succeeded. The probe injected server-side intent and therefore did not validate mouse/keyboard input, release, dynamic targets or a remote peer. The wall and probe were temporary and did not change the saved scene.

On 2026-11-03 a Windows development client connected over loopback to the Editor host; both player objects appeared on the host. A development-only automated client sent movement and jump RPCs: its observed displacement was 3.10 m and its jump was 0.47 m. A separate host-side temporary probe confirmed that a hand attached to the spawned network crate and released it. The probe temporarily disabled crate gravity during acquisition; it did not validate carrying the crate, contention, crate replication on the client or mouse/keyboard input.

For online play, link the project to Unity Cloud in **Edit > Project Settings > Services**, enable Relay for that cloud project, and rebuild via **Tools > Conductor Chaos > Build Windows Client**. Use the same build on each machine. Choose **Online hosten**, share the Relay code, and have guests enter it and choose **Deelnemen**. The host chooses **Start samen** once everyone is connected. The game signs players in anonymously through Unity Authentication. **Spelen** starts a solo game without Unity services.

Follow-up host probe on 2026-11-03 confirmed weighted legs, enabled arm/torso contacts, 2 mm maximum collider penetration during movement, 39.6 degrees of leg rotation, and grip release after an injected server RPC. It did not cover every pose or actual operating-system mouse input.

A separate development client connected to the Editor host and observed 2.93 m of movement, a 0.21 m jump and 17.2 degrees of replicated leg rotation. This automated input did not exercise a remote client's grip release or packet loss.
